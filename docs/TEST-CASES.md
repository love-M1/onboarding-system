## 端到端验收流程

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | HR 登录并创建一个启用部门责任人账号 | 责任人与模板责任部门一致，可正常登录 |
| 2 | HR 创建员工，入职日期不晚于今天 | 自动按模板生成任务，责任部门和截止日期正确 |
| 3 | 员工登录并上传 PDF | 状态变为“待部门确认”，历史中可下载附件 |
| 4 | 部门责任人登录并查看本部门任务 | 只显示本部门任务，可查看材料和历史 |
| 5 | 部门责任人填写原因、选择新截止日期并退回 | 状态变为“已退回 · 待补交”，未自动算逾期 |
| 6 | 员工查看退回原因并重新提交 | 状态回到“待部门确认”，旧记录和附件保留 |
| 7 | 部门责任人确认完成 | 状态变为“已完成”，记录确认人和确认时间 |
| 8 | HR 查看档案详情与进度汇总并归档 | 完成数正确，存在任何未确认任务时归档被阻止 |

## 发现与修复记录

| 问题 | 原因 | 修复结果 |
| --- | --- | --- |
| 旧版任务被直接确认完成 | 旧 `/finish` 接口跳过员工提交和部门审核 | 删除旧接口，全部迁移到提交、确认、退回三接口 |
| 状态为待确认或已退回时仍能归档 | 未完成统计只检查状态 0 | 改为统计状态 0、1、3，并增加回归测试 |
| 退回后立即显示逾期 | 未区分按时退回和迟交场景 | 按时退回显示“待补交”；仅原截止日已过、提交迟交或新截止日已过时计算逾期 |
| 前端可生成不存在的演示任务 | 旧任务页固定拼出 5 个 `demo-*` 任务 | 改为完全由后端任务记录驱动，模板为空时不显示虚假任务 |
| 前端提交只修改本地展示状态 | 未调用 multipart 真实提交接口 | 改为发送真实 `File` 对象和备注，并刷新后端详情 |
